# requirement-clarification（95% 理解门）

> 灵感来源：本 skill 的雏形来自抖音一条评论区的讨论，经作者长期使用、多轮修改完善，现开源供大家使用、修改、分发。

## 这是什么

一个「先澄清、再动手」的需求澄清流程：收到复杂或有副作用的任务时，先**只读侦察现状** → **复述理解** → **列阻塞性问题** → 双方理解度都 **≥95% 才执行**，未达标就迭代提问。

## 三条准则

- **代价说死**：把技术代价、严重程度、不确定性讲清楚，不替用户宣布成功。
- **证据优先**：结论附来源（文件:行号 / 命令输出 / 进程 ID），不用「应该没问题」。
- **诚实**：不确定就说不知道，被拦了如实报告。
